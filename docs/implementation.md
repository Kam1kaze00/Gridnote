# Design and verification

## Writing and selection

Gridnote reads native tablet samples on macOS and coalesced Pointer Events in the portable editor. The native input handler also accepts a driver’s right-click and middle-click mapping. It clears transient button state when focus or proximity changes. The upper switch arms one erasing contact, and a held lower switch consumes movement for vertical scrolling. Device profiles supply adjustable defaults and account for pressure and button availability. [Apple tablet events](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTabletEvents/HandlingTabletEvents.html) · [Wacom app-specific settings](https://101.wacom.com/userhelp/en/AppSpecificSettings_Full.htm) · [Pointer Events](https://www.w3.org/TR/pointerevents3/) · [Apple Sidecar](https://support.apple.com/en-us/102597)

The pen preserves its endpoints, protects sharp changes in direction and limits the correction applied to near-straight samples. Both editors reduce the correction on faster samples using their timestamps. A cached pressure outline keeps a dense page inexpensive to repaint. Highlighter strokes apply transparency and multiply blending. Selector and eraser options use whole-stroke intersection tests. [Casiez et al. on the jitter and lag tradeoff](https://gery.casiez.net/1euro/) · [Goodnotes eraser](https://support.goodnotes.com/hc/en-us/articles/7353718249231-Erase-handwriting-and-page-content-with-the-Eraser-tool) · [Goodnotes highlighter](https://support.goodnotes.com/hc/en-us/articles/7353718215823-Using-the-Highlighter-tool)

Tool settings stay attached to the toolbar. Dragging a selection compares its edges and centers with visible, unselected objects in a four-screen-pixel tolerance. The transient alignment guides stay out of the notebook and PDF. Tables retain independent width, height, header and cell values. Exact sizing and dragging operate on the same object. [Apple toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars) · [Apple popovers](https://developer.apple.com/design/human-interface-guidelines/popovers) · [Freeform alignment guides](https://support.apple.com/en-mt/guide/freeform/-frfma75f5f63/mac) · [Numbers table sizing](https://support.apple.com/en-gb/guide/numbers/tancea35ff59/mac)

## Paper, PDF and capture

The document uses top-left coordinates in PDF points and a continuous sequence of A4 pages. The Mac canvas and PDF export share a Quartz renderer. The portable client shares the object model and uses PDF.js and pdf-lib. It preserves the appearance of an imported PDF by rasterizing its page backgrounds at export, while handwriting and grid lines remain vector paths. Use the native Mac exporter when selectable source PDF text matters. [Quartz PDF drawing](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/drawingwithquartz2d/dq_pdf/dq_pdf.html) · [PDF.js](https://mozilla.github.io/pdf.js/) · [pdf-lib](https://pdf-lib.js.org/)

A touch device requests the rear camera. When live camera capture is unavailable, an image input delegates capture or photo selection to the device. Cropping happens locally. The inserted photo is placed on the page that was active when capture began. The macOS share picker receives a PDF file URL. A web share starts from a user click with a prepared PDF file after the browser reports file-sharing support. Email, WhatsApp and other destinations depend on the system’s installed share extensions. [Media Capture](https://www.w3.org/TR/html-media-capture/) · [AppKit sharing items](https://developer.apple.com/documentation/appkit/nssharingservicepicker/init%28items%3A%29) · [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API)

## Persistence and portability

Files store edit geometry, pressure samples, text, embedded images, imported PDF data and per-page paper. The Mac reader migrates earlier property-list notebooks. The web client uses an IndexedDB transaction for document and recovery records, and detects revision conflicts. Standalone assets, including OCR data, use a versioned offline cache. Desktop launchers embed those same assets and keep a stable loopback origin. [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) · [PWA installation](https://web.dev/learn/pwa/installation/) · [Go embedded files](https://pkg.go.dev/embed)

## Code and Solve

Code is stored verbatim as editable text with a per-block coloring setting. A lightweight lexer colors common strings, keywords, numbers and comments. The same bounded algebra parser runs in JavaScriptCore and the browser. It recognizes supported arithmetic and single-variable equations and includes a small set of code patterns with locally explainable results. OCR runs on demand using Apple Vision or Tesseract.js with bundled English data. Explanations for arbitrary code, missing context and open-ended questions use the optional API server or an explicit handoff to ChatGPT. [Syntax-highlighting examples](https://highlightjs.org/examples) · [Apple Vision text recognition](https://developer.apple.com/documentation/vision/recognizing-text-in-images) · [Tesseract.js](https://github.com/naptha/tesseract.js) · [OpenAI developer quickstart](https://developers.openai.com/api/docs/quickstart)

## Checks

- The native AppKit suite exercises the editing window, input events, clipboard, whole-stroke erasing, selection transforms, paper, undo and redo, page deletion, settings panels, save errors, recovery, zoom restoration, tables and code blocks. A second process test kills the editor after autosave and verifies that the draft and caret return.
- Chromium, WebKit and Firefox automation on macOS exercises table dragging, numeric dimensions, cell autosave and reopening, highlighter and shapes, code coloring, equation solving, local image OCR, PDF preview and matching file contents for Share and Save. The file-share receiver is simulated.
- Mobile input tests simulate finger and pen input and a rear camera. They check the requested facing mode, image crop, target page, released media tracks and viewport width.
- The rotated and cropped PDF fixture was exported from both clients and rasterized at 640 pixels high. The resulting visible text bounds agreed within one pixel. A generated example PDF was checked for standard A4 page dimensions.
- Hardware button mapping, actual camera optics, installed share destinations, and pen feel need hands-on checks on the target device. API request formatting and response handling have fixture tests. A live paid AI request requires a configured key.

Run `Tests/native.sh` on macOS and set `GRIDNOTE_TEST_FULLSCREEN=1` in an unlocked graphical session to include a real fullscreen Space. Run `node Tests/solver.cjs` and `python3 Tests/test_server.py` for the offline solver and API adapter. The browser tests use Playwright, a built site at `GRIDNOTE_URL`, and `ENGINE=chromium`, `webkit` or `firefox`. The default test server is `http://127.0.0.1:8793/`.


## Editing and recognition details

The launcher uses connected USB product labels where the OS exposes them. Web clients use pointer type and reported pressure, with optional previously authorized HID labels on desktop. Tablets skip the device picker. Upper-switch erasing was checked with a physical One by Wacom CTL-672 on macOS. Pen width presets use a bounded pressure curve; Fineliner and the pressure-off setting produce constant width. Regular erasing cuts editable fragments along the swept tip path. [W3C Pointer Events](https://www.w3.org/TR/pointerevents/) · [WebHID device discovery](https://developer.chrome.com/docs/capabilities/hid) · [Goodnotes pen styles](https://support.goodnotes.com/hc/en-us/articles/7353756785679-Write-and-customize-ink-with-the-Pen-tool) · [Xournal++ erasers](https://xournalpp.github.io/guide/tools/eraser/)

The page organizer reorders PDF background references, page styles and editable objects in a single undoable document change. The thumbnail list renders visible sheets on demand. Text removal retains handwriting, code blocks, images and populated tables. [Adobe page organization](https://helpx.adobe.com/acrobat/web/edit-pdfs/organize-documents/organize-pages.html)

Solve reads available PDF text and scans a cropped image of the page. Blank paper ruling and highlighter are omitted from the standalone ink scan. A photo containing one word problem can supply several lines of givens and its diagram. Recognition alternatives can propose a variable at a coefficient boundary, with the crop and editable text available for review. A visually ambiguous letter or decimal point may still need correction. The explicit Ask AI action sends the displayed crop and text. [Apple Vision recognition alternatives](https://developer.apple.com/documentation/vision/vnrecognizedtext) · [Tesseract image quality](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)

## Drawing performance

During pen contact the portable renderer reuses the visible page background and fits a short live tail. Both clients reuse completed portions of long stroke previews. On lift, all recorded samples feed the final editable curve. The physical pen position and the newest recorded sample are never delayed to wait for future points. [W3C coalesced input events](https://www.w3.org/TR/pointerevents/)

A local WebKit benchmark on macOS used a 240-stroke page, a 1,280-sample live stroke, an 820 × 960 viewport and a 2× backing scale. Across 155 measured frames the 95th-percentile JavaScript paint callback went from 3 ms to 1 ms at 1-ms timer resolution. A separate optimized AppKit benchmark rendered 240 completed strokes into a 1200 × 1640 bitmap in 4.23 ms median. These measure rendering work on the test Mac. Physical tablet input and display latency need separate hardware measurements.


## Offline installation and public builds

The portable launcher and notebook menu report readiness after service-worker activation. Installation caches the editor, fonts, PDF renderer and OCR data before activation. Failed installations remove their partial cache and a later online launch retries. Browser tests interrupt a first install, retry it and reopen an edited notebook offline. The hosted Solve panel offers offline calculations and a clipboard handoff. The direct AI action appears on the local study server and desktop launcher. [Service worker lifecycle](https://developer.chrome.com/docs/workbox/service-worker-lifecycle) · [iPad Home Screen apps](https://support.apple.com/guide/ipad/ipad8f1f7a29/ipados) · [Chrome web app installation](https://support.google.com/chrome/answer/9658361)

The release packager exports a single Git revision, builds both Mac architectures and four Windows/Linux launchers, checks ZIP integrity and writes SHA-256 digests. The portable builder stages an explicit list of client sources and pinned dependencies. It reports unexpected entries in a reused destination before copying any files into it.

## Appearance

Both clients store the interface theme locally and share the launcher and subject-panel assets. The first launch uses the Drafting Room illustration. Each of the five themes has a distinct toolbar mark, tool artwork and type. Pixelated uses discrete filled cells and Pixelify Sans. Tokyo Neon uses Barlow Semi Condensed. Cyberpunk uses IBM Plex Mono. The fonts and their OFL notices ship in the application. The notebook stores stationery separately so existing exercises retain their page design when they open on another device.

The Tokyo wayfinding palette draws on [Tokyo Metro’s route symbols](https://www.tokyometro.jp/lang_en/station/202303_number_en.pdf). The handheld design takes its four tones from the [original Game Boy display](https://www.nintendo.com/en-gb/Hardware/Nintendo-History/Game-Boy/Game-Boy-627031.html). The terminal uses [IBM Plex](https://www.ibm.com/plex/). Interface graphics follow [W3C’s guidance on non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

Image placement maps source pixels and declared print density to PDF points. PNG stores pixels per metre in [the pHYs chunk](https://www.w3.org/TR/png-3/#11pHYs). Images without a density use the [CSS reference ratio of 96 pixels per inch](https://www.w3.org/TR/css-values-4/#absolute-lengths). Camera crops retain their decoded pixel grid. Corner dragging reports millimetres and compares against visible unselected objects. Guides and size labels are transient editor overlays.

Stationery belongs to the notebook. The optional cartoon flag in the page design is preserved on save, undo, page moves, PDF export and transfer between the Mac and portable apps. The renderer draws the grid and margin as vectors. It draws the folio and mascot below students’ writing. Existing pages retain their chosen paper when a different interface theme is selected.
